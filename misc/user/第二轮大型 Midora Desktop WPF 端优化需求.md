# 第二轮大型 Midora Desktop WPF 端优化需求

## 概述

本文档是用户试用了第一轮优化后的软件后列出的第二轮优化需求。

## 交互

### Velocity 编辑柱状视图的问题和优化

- 单纯点击某个音符位置上的某y位置上，我希望把这个位置上的音符力度全部调到点到的y值 -> 力度。

- 鼠标指针不对，而且在柱子左右边界处，鼠标指针也不应该变，请用单纯的默认指针。

- 除了一个：我希望单独点某个柱子的顶部边界拖动时，单独上下调整力度，此时指针变化成上下指针。

- 在Tick 0处，鼠标拖动到了 x=0 位置本身的力度也应该立即变化，而不是移到了范围外后才变。

- 我希望在未选择任何音符时，拖动编辑按照现在的，作用于拖动到的所有音符；在选择了某个/某些音符后，拖动编辑只作用于拖动到的且已选择的音符上。

### Parameter Lane & Event/Curve Lane

- 可以错误地将视图范围“移到”范围之外，但左边的基准值数字却不变。很怪。

- 在缩小范围后，垂直移动视图时，只能以非常大的单位移动，希望以小单位移动。并且，似乎无法移动到顶部，却能无限往下移动视图。

- 缩小范围后，垂直移动视图时，左边的基准值数字也不变，这不对。

- 这里的交互逻辑和显示逻辑建议重写，按照一般的 DAW 的事件编辑逻辑即可。

- Velocity 视图也有相同的问题，能往下面无限移动，垂直移动视图时左边的基准值也不变。

### 钢琴卷帘可以错误地往下无限移动视图

永远不应该让视图超出0-127范围。

现在能超出0以下，而127以上倒是没有超出。

## 纯 UI 问题

### 顶部的时间+BPM显示，字体颜色错误地使用了黑色，应该用亮色

另外，时间和BPM之间可以加个竖线隔开。

### 禁用状态的无边框按钮虽然已经修没了边框，但仍然有背景色，应该去除

### 顶部的播放按钮，图标右边被截断，但是停止按钮和循环按钮都正常

### 音符位于Segment的Tick 0时，在轨道视图中，Segment不显示位于Tick 0的音符

### 轨道视图中，Segment内的预览音符，希望能直接看出音符们的垂直位置，而不是现在的一维图

也就是说，希望能在轨道视图就能看出 Segment 内部的音符大概是什么二维排布。

为了简单，轨道视图中的 Segment 预览的 Key 范围直接定死为 [0, 127]，音符高度最小 1 像素，音符位置四舍五入。

保持手动渲染的方式。该视图预览内容应做按 Segment 的缓存机制，Segment 变化时再更新缓存。

### 选择的内容的高亮，请用更亮的红色框，现在选择的内容对比不明显

### Segment 编辑视图里，底部力度/逻辑参数编辑视图，希望能调整高度，并且能隐藏/显示

### Parameter Lane & Event/Curve Lane 的白色边框希望去掉，视觉非常突兀

### 钢琴卷帘，现在的斑马颜色是黑键浅、白键深，我希望反过来。

### Parameter Lane & Event/Curve Lane 的左侧数字若在底部/顶部，数字会超出视图垂直范围，应该将处于边界处的数字自动往上/往下移动一点

### Grid和Step的下拉框

UI 行为非常怪，包括逻辑音轨视图、Segment钢琴卷帘视图、SubVoice钢琴卷帘视图都有这个问题，我不知道如何复现。

- 莫名其妙出现红色方形边框（不是焦点的那个红色边框，而是外面又多了一层非圆角的方形边框），有时候方框消失

- 数字有时候消失不显示了，下拉的内容正常，但选择后框内仍然没有数字，不知道干了什么之后，数字又显示了，但有时只显示其中一个。

- 但操作行为是对的，选择下拉项确实被应用了，但就是有时候不在框里显示选择的项。

- 框内应该只显示 1/8 1/32 这种，而不是全称，不然放不下那么多字。

- 那行控件的顺序调整为：[Grid] 下拉框 | [Snap] 下拉框 | Length [ ] Vel [ ] | [-] [+] | [Draw] [Select] [Erase] （不要那个“Step”文字了，然后按照我给的位置加加竖线）
