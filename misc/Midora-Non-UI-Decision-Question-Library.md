## 1. 使用规则

- **小决定**：不同选择影响局部、兼容面小且容易修改。实现方先按推荐方案实施，同时登记完整依据、影响和替代方案；产品所有者随后确认或要求修改。
- **大决定**：会改变可听结果、持久化兼容性、公共接口、确定性、并发模型、发布形态或大范围工作流。对应分支在决定前不实施；不受影响的工作继续。
- 每个问题必须记录：SRS/源码依据、事实与不确定性、影响范围、推荐方案、备选方案、当前实施状态、产品回答和最终处理提交。
- 已回答问题保留原编号，不删除，作为决定审计链。

## 2. 当前开放问题

### Q-NUI-001：损坏内嵌 SF2 的再次保存表示

- 类型：大决定
- 状态：待确认；仅暂停损坏内嵌 SF2 的普通保存 / 保存副本分支
- 发现日期：2026-08-06
- SRS 依据：第 6.7.1、6.7.3、16.7.6、16.15.4、16.21.3、16.27.4 节。
- 已确认事实：内嵌 SF2 的 settings hash、manifest hash、未压缩实际字节及文件大小必须一致；导入与写包必须流式处理；hash 不匹配或资源损坏不阻止 Project 打开，不标记 Project 已修改，也不阻止普通保存 / 保存副本；被动资源状态不得改写 `soundfont-settings.json`。
- 不确定点：SRS 要求损坏资源保存时“写出当前内存 Project 中的 SoundFont Settings 与可用资源状态”，但没有定义在当前 Embedded 引用仍存在、预期 hash/size 不得被动改写，而唯一可用资源字节已经与预期身份不一致或完全缺失时，新包应采用何种合法表示。继续写损坏字节或只写 settings 会违反三方一致性；清空引用会违反不得被动修改 Project；拒绝保存又违反明确的允许保存规则。
- 影响范围：`.midora` v1 文件兼容性、损坏恢复工作流、普通保存与 Save Copy 原子事务、自校验、资源诊断，以及未来 UI 对损坏资源的操作提示。
- 推荐方案：把“允许保存”解释为保存前必须由用户明确选择一种修复动作；无动作时保存事务进入可恢复的资源决定状态而不发布文件。可选修复动作固定为：重新绑定 / 替换内嵌 SF2，或明确清除 SoundFont 引用。完成任一动作后写出的包重新满足 settings、manifest、实际字节三方一致。该方案不静默改变 Project，也不生成新的已知损坏包。
- 推荐依据与限制：它保持严格格式不变量和用户数据控制，且不会把损坏字节伪装成合法资源；但严格说会把 SRS 的“允许普通保存和保存副本”收窄为“完成显式修复决定后允许”，因此必须由产品所有者确认或修订 SRS。
- 备选方案及差异：A. 原样保留损坏字节并让 settings 保持预期 hash：保存可直接进行，但故意生成三方不一致的新包。B. 保存 settings 但省略资源：仍生成已知损坏包，且资源从可恢复字节变为缺失。C. 保存时静默清空 Embedded 引用：生成结构合法包，但被动改变 Project 源语义并可能丢失恢复线索。D. 保存时把 settings hash/size 更新为损坏字节实际身份：结构合法，但把被动损坏内容当作用户接受的新资源，违反已确认的主动接受规则。
- 当前实施状态：正常 Embedded SF2 导入、会话期临时资源租约、流式 package 写出、严格打开校验与损坏诊断继续实施；本问题涉及的“损坏后再次保存”不实现临时默认值。
- 需要产品所有者回答：请选择推荐方案，或在 A～D 中选择并说明是否同时修订第 16.15.4 节的三方一致性 / 允许保存规则。若选择推荐方案，还需确认保存入口应直接失败并给出修复动作，还是由应用层在调用持久化事务前保证已完成修复动作。
- 产品回答：待填写。
- 最终处理与提交：待填写。
