# Midora WPF 样式样例需求追踪

> 状态：产品所有者已通过视觉评审，作为后续正式 UI 的默认视觉基线；样例本身仍不是正式 Midora 主界面实现
>
> 日期：2026-08-08

## 1. 输入与依据

- 用户指定的视觉方向：暗色、黑色与红色为主、简约。
- 视觉复审反馈：单行文本不得裁切；数值文字必须保持亮色对比；标题栏按钮为直角方形；Tick/BPM 垂直居中；按钮焦点使用低强调虚线轮廓，按下态必须与静止态明显可辨。
- 图标来源采用 Microsoft Fluent System Icons 官方 20 px SVG 路径；样例固定记录上游 revision 与 MIT notice，不使用字体文件或额外 WPF 图标包。
- 第二轮视觉复审反馈：标题栏最小化、最大化、还原和关闭图标改用用户指定的四个 SVG；图标布局尺寸固定为 `10 × 10` 并启用 Layout Rounding；最小化线必须清晰落在单个像素行；Project Panel 搜索框及文字不得裁切，搜索图标垂直居中；最大化窗口必须严格限制在当前显示器工作区内，不得覆盖任务栏或把标题栏按钮推到屏幕外。
- 第三轮视觉复审反馈：三个窗口控制图标的视觉亮度一致；顶栏命令图标缩小；数字徽标和增减图标居中；输入框只应用一次内边距；Expander 标题不得裁切；一级菜单文字居中且选中背景贴合底部分割线；滚动条轨道与 Thumb 完整显示；最大化时移除外边框；窗口控制按钮保持箭头指针。
- SRS 第 17、18、20 章规定的主窗口区域、编辑工作区、通用交互、验证与可访问性要求。
- SRS 第 3、13、19、22 章规定的 Project 生命周期、播放/预览状态、任务工作流和跨系统边界。

### 1.1 产品所有者批准决定

- 2026-08-08，产品所有者在完成三轮截图与真实窗口复审后确认该样例“基本上完美”，并明确要求以后默认按此样式开发。
- 因此，`src/midora-desktop/Midora.Desktop.StyleGallery/Themes/` 中的 Palette、通用 ControlTemplate、Fluent 图标 Geometry 和 WindowChrome 行为构成后续正式 UI 的默认视觉实现基线。
- 正式 UI 应直接复用、迁移或从这些资源派生，不得建立平行视觉 token、复制后静默分叉，或在没有新视觉反馈时恢复为 WPF 系统默认样式。
- 后续产品所有者明确提出的视觉修改优先于本基线；发生修改时应同步更新本追踪文档和对应资源，继续以 100% DPI 实际窗口复审为准。
- 本决定只批准视觉语言、控件状态和窗口行为。样例中的静态数据、布局占位、按钮动作和编辑器示意不构成正式业务行为批准。

## 2. 本轮正式输出

- 一个独立的 `win-x64`、`.NET 10`、纯 WPF 样式样例程序。
- 一个可滚动的组件画廊，用静态示例数据展示：
  - 主窗口框架、菜单、命令栏、播放控制、状态栏；
  - Project Tree、Workspace Tabs、Inspector、Diagnostics/Tasks；
  - 按钮、图标按钮、文本输入、下拉框、数值输入、复选框、单选框、开关、滑块、进度条、标签、提示和空状态；
  - Midora 可能使用的 Arrangement、Segment、Piano Roll、Mapping 列表、诊断行和任务进度等视觉原型；
  - 正常、悬停、焦点、选中、只读、禁用、警告、错误、损坏和加载中等状态。
- 标题栏、命令栏、传输控制、搜索、增减按钮、Project Tree、状态卡片等主要图标使用 Fluent System Icons Geometry 资源。
- 标题栏四种窗口控制图标例外：仓库保留用户指定 SVG 的内容副本，并使用相同路径数据生成 WPF Geometry；路径按自身可见边界等比归一到 `10 × 10`，最小化图标单独启用 aliased edge rendering。按用户要求，不记录这四个文件的来源信息，也不为其建立单独授权核验项。
- 样例内用户界面文案使用英语，符合初版固定英语界面的要求。

## 3. 边界与不变量

- 样例不读取、创建或修改 `.midora` 文件，不建立 Project 领域模型。
- 样例不调用 Compiler、Playback、MIDI Export、Audio Render 或原生音频后端。
- 所有轨道、Segment、诊断、状态和进度都是明确的静态展示数据，不代表业务逻辑已实现。
- Mute/Solo 只作为运行时监听控件的视觉示例，不写入任何持久化状态。
- 颜色不是状态的唯一载体；重要状态同时带图标或文字标签。
- 内容区各自滚动；不设计跨整个工作区的双向滚动容器。
- 以 100% Windows DPI 为本轮正式视觉检查基线，同时保留 WPF 原生 DPI 缩放行为。
- 自定义 WindowChrome 在 `WM_GETMINMAXINFO` 中按 `MonitorFromWindow` 对应显示器的 `rcWork` 设置最大位置和尺寸；不使用主显示器固定高度或当前任务栏高度常量。

## 4. 失败条件与诊断

- 工程无法在仓库固定 SDK 下还原或构建。
- 运行时出现未处理异常、资源解析失败或控件模板错误。
- 最大化后的实际 Window Rect 不等于目标显示器 Work Area，或任务栏遮挡主窗口底部。
- 标题栏图标未落在相同的 `10 × 10` 布局框内，最小化线跨越多个像素行，或窗口控制组右缘超过工作区。
- 黑红主题在常用控件弹出层、焦点态、禁用态或滚动条中退回不可接受的系统浅色样式。
- 1280×800 或主窗口最小尺寸下核心命令、Workspace 和状态信息不可到达。
- 状态只用颜色表达，或文本对比度、焦点边界明显不足。

## 5. 持久化与运行时归属

- 本轮没有 Project 持久化内容。
- 样例窗口尺寸、折叠状态、选择状态和控件值只在当前进程内存在，不保存为 Application Preference，也不进入 Undo/Redo。
- 视觉常量集中于 WPF ResourceDictionary，供本样例统一消费；产品所有者已确认这些资源作为未来正式 UI 的默认基线。正式 UI 接入时仍需按生产工程结构迁移，并保持单一 token 来源。

## 6. 明确非目标

- 不实现正式 Midora 主窗口、编辑器行为、命令路由、快捷键体系或业务数据绑定。
- 不确认最终品牌标识、字体、动画规范或尚未出现在样例中的全部像素尺寸；本样例已采用 Fluent System Icons 作为已批准默认图标体系。
- 不新增 UI 框架或第三方控件依赖。
- 不改变 SRS、领域公共接口、持久化格式、并发模型或可听语义。

## 7. 本轮验收方法

1. `dotnet restore --locked-mode` 与 `dotnet build --no-restore` 成功。
2. 启动样例，在 100% DPI 下检查首屏、滚动区域、ComboBox/ContextMenu/ToolTip 弹出层及键盘焦点。
3. 检查窗口最小尺寸下仍可访问中心样例区、播放控制和底部状态。
4. 产品所有者已完成三轮视觉评审并批准当前参数为默认基线；后续明确反馈仍优先于当前具体数值。
5. 对普通和最大化标题栏做像素截图；检查最小化为 `10 × 1`，最大化、还原、关闭可见边界为 `10 × 10`，三按钮中心保持 46 px 等距。
6. 比较最大化 Window Rect 与当前 Monitor Work Area，并检查最大化底部状态栏完整可见。

## 8. 已完成的验收证据

- `dotnet restore --locked-mode` 成功；Release `dotnet build --no-restore` 成功，0 warning、0 error。
- 普通窗口尺寸为 `1440 × 900`；最大化 Window Rect 与当前显示器 Work Area 均为 `1920 × 1032`，任务栏未遮挡底部状态栏。
- 最大化后外框像素由普通窗口的 Border Strong 变为标题栏背景，WindowChrome resize border 同步设为 0；最顶部关闭按钮区域 `WM_NCHITTEST = HTCLIENT`，标题拖动区域为 `HTCAPTION`。
- 标题栏四个图标均处于 `10 × 10` 布局框；最小化图标为清晰 `10 × 1` 单像素线。普通状态下最小化像素主色为 `RGB(126,133,142)`，与最大化图标主像素一致。
- 顶栏命令图标统一为 `14 × 14`；数字徽标内容中心与外圈中心误差不超过半个物理像素；增减图标在按钮内容区中心误差不超过半个物理像素。
- TextBox 重复 Padding、Expander 标题裁切、一级菜单底部间隙和垂直 ScrollBar 被限制为 `10px` 高的问题均已通过实际窗口截图复核关闭。
- 窗口控制按钮悬停时系统 Cursor handle 与 `IDC_ARROW` 一致。
